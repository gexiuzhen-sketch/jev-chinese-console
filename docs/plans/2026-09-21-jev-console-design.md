# Jev 中文操作台设计

## 产品目标

为普通用户提供一个不需要编写 JSON 的 Jev 体验网站。用户粘贴待判断内容，通过表单选择“是否判断（Noul）”“多选一（Choice）”或“等级评分（Score）”，提交后查看答案、概率、置信度、模型版本与耗时。

网站部署在 `jev.lumingzt.cn`，TypeSafe API Key 仅保存在服务器环境变量中，不发送到浏览器。

## 用户与额度

- 匿名访客：按经过 HMAC 匿名化的 IP，每个上海自然日最多 10 次。
- 登录用户：每个账号每个上海自然日最多 30 次。
- 匿名额度用尽后，界面引导用户注册或登录。
- 登录账号额度用尽后，明确显示次日重置，不继续调用 TypeSafe。
- 注册与登录接口另设短时频率限制，减少撞库和滥用。

## 体验范围

首屏就是工作台，不设置营销首页。桌面端采用三栏结构：待判断内容、问题配置、判断结果；移动端依次堆叠。

问题配置全部采用中文表单：

- Noul：填写一个是否问题。
- Choice：填写问题及 2–6 个候选项，可为每项补充说明。
- Score：填写问题及 2–6 个从低到高的等级描述。

提供少量示例用于快速上手，但不保存用户提交内容和 Jev 结果。

## 技术架构

- Node.js 20 + Express 提供静态页面与同源 API。
- `@typesafe-ai/sdk` 在服务端调用 `jev-latest`。
- SQLite 保存账号、会话和每日额度计数。
- bcrypt 保存密码哈希；随机会话令牌仅以 SHA-256 哈希形式入库。
- Nginx 终止 HTTPS，并反向代理到仅监听 `127.0.0.1` 的 Node 服务。
- systemd 守护进程负责自动启动与异常重启。

## 安全边界

- TypeSafe Key、会话密钥和 IP 哈希密钥不进入仓库或前端。
- 所有 Jev 请求在服务端进行；输入长度、问题类型和候选项数量均严格校验。
- 数据库查询全部参数化；页面只用文本节点显示用户内容和模型结果。
- Cookie 使用 HttpOnly、Secure、SameSite=Lax。
- 写接口校验同源 Origin，并设置 CSP、HSTS、X-Frame-Options 等响应头。
- 不记录完整用户输入、密码、会话令牌或 API Key。

## 部署与验证

应用部署到 `43.136.38.87` 的独立目录与 systemd 服务，新增单独的 Nginx server block，不修改现有站点。申请 `jev.lumingzt.cn` 的 Let’s Encrypt 证书后，验证首页、注册登录、匿名/登录额度、Jev 三类问题、移动端布局和异常提示。
